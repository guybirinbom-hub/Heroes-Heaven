  `theirAssertions`, which now calls it instead of `parseOps(...).flatMap(flattenOps)`).
  It walks their operation tree carrying gate context and DROPS any MAX_HEALTH_* op that sits inside a
  `conditional IF FEAT_NAMES INCLUDES "<x> resiliency"`. Scoped to MAX_HEALTH rather than to the whole
  conditional, so a future sibling op under the same gate is still compared.
  WHY (in the code comment): AoN feat-6214 (Monk Moves) prints only "You gain a +10-foot status bonus
  to your Speed when you're not wearing armor" — no Hit Points. AoN feat-6212 (Monk Resiliency) prints
  "3 additional Hit Points for each monk archetype class feat you have"; WG has no per-archetype-feat
  verb, so it stamps a gated +3 onto every qualifying feat row. We hold that sentence ONCE, where it is
  printed: feats/monk-resiliency.maxHpBonus {perArchetypeFeat:3, archetype:'monk'} (read derive.ts:895 /
  build.ts:8111).
- scripts/wg-values.mjs, SETTLED_VALUES: THREE now-dead settles DELETED with the citation
  `// batch 031: monk-moves#hp` on their own lines — 'barbarian-dedication' ['hp|'],
  'monk-dedication' ['hp|'], 'exemplar-dedication' ['hp|']. They were three named instances of the same
  59-row corpus shape; the teach replaces them. ONE TEACH, minus three settles — not N settles.

  guardian, plus Starfinder's operative / soldier / solarian).
