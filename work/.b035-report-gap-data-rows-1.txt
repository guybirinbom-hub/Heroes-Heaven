WHAT THE DEFECT WAS, AND WHAT I MEASURED
────────────────────────────────────────────────────────────────────────────────────────────────
A `whileActive` clause authored ON a record is scanned off that record, which carries a `name`, so
the IWR breakdown says "Ligneous Instinct". A clause the player CHOSE arrives through
`applyAlwaysOn` → `mergeEffect` into `Character.chosenEffects` — ONE shared DefenseGrants bag
merged from many records — which has no `name` at all, so derive.ts's `ownedWhileActive` had
nothing to attribute it to and pushed the bare fallback string.

MEASURED before the fix, on a built 9th-level Rime dragon-instinct barbarian with rage on:
  deriveDefenses(c, db).sources['resistance:piercing'].map(s => s.from)  ===  ['Active state']
  deriveDefenses(c, db).sources['resistance:cold'].map(s => s.from)      ===  ['Active state']
  stateGrantSummary(c, db, 'rage').map(e => e.from)                      ===  ['Active state']
and the same on a Giant Instinct barbarian who picked fire (bludgeoning + fire, both 'Active
state'). The Rage card — the "what will entering this state give me" index — was blind the same
way, which the builder's note had not covered. That is every instinct that asks a question:
dragon, giant, superstition. raging-resistance.test.ts:64 had already closed the identical hole
for the instincts that ask none.

Print is the authority for the attribution, not just for the numbers:
  AoN instinct-9 (Dragon): "You resist piercing damage and the damage type of your instinct's
    dragon breath." — ONE sentence, printed on the instinct, producing BOTH breakdown lines.
  AoN instinct-4 (Giant):  "You resist bludgeoning damage and your choice of cold, electricity, or
    fire, chosen when you gain raging resistance." — likewise.
A line the sheet cannot trace back to the feature that granted it is the thing the breakdown
exists to prevent.

────────────────────────────────────────────────────────────────────────────────────────────────
THE FIX
────────────────────────────────────────────────────────────────────────────────────────────────
src/rules/build.ts
  `mergeEffect(into, g, srcName?)` — the whileActive branch now pushes a COPY of each clause with
  `from: srcName` stamped on it when a source name is known. A copy, not a mutation: `g` is the
  shared content record, and stamping it would have leaked the first character's instinct name
  into the database for every later build. `applyAlwaysOn` already receives `srcName` (it uses it
  for innate-spell source labels and creature-trait pills) and simply passes it through, so no
  call site changed and no new lane was invented — every `applyAlwaysOn` caller already supplies
  the record's own `name`. `mergeEffect` has exactly one caller, so the optional third argument
  cannot silently miss a path.

src/rules/derive.ts
  `ownedWhileActive`'s scan reads `wa.from ?? g?.name ?? 'Active state'`. The record-scanned path
  is untouched and still reads its name off the record; the fallback is untouched and still exists
  for a clause that genuinely has no owner. `activeStateGrants` and `stateGrantSummary` share this
  one walk, which is why one read fixes both the IWR breakdown and the Rage card.

Both edits carry a WHY comment quoting the printed clause, per the batch rules.
No data row was needed or authored: the data was already correct — this was a reader that dropped
a fact it had been handed.
