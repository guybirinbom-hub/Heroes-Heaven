  THE FIX, exactly as the gap line prescribes — "a conditional-only line fed from defenses.sources
  keys that have no res entry":
    · src/rules/derive.ts:3019 — new export `conditionalResistances(def)`, derived from the attribution
      map: every `resistance:<type>` key with no entry in `def.resistances`, valued at the best single
      source (the same no-stacking rule the counted list uses). Derived rather than folded into
      `resistances`, because folding is precisely what the `res.set` skip exists to prevent.
    · src/sheet/DefensesPills.tsx:69 — its own "Situational resistances" row, reusing the existing
      `pill()` (so the `*` conditional marker and the StatDetailModal breakdown come for free). The
      component's `has` guard now counts these too: a character whose ONLY defence is conditional
      previously rendered nothing at all.
    · src/sheet/VitalsRail.tsx:799 — the same row in the Defenses card, reusing IwrTerm; the card's
      own render guard likewise now counts them.
  This also un-silences the one carrier already shipped, modes/dampening-harmonics (resistance 10
  against spell/magical-ability damage of the magiphage trait), which had the same fate.

  PINNED BY test/batch036-gap-data-rows-2.test.tsx, four tests on a BUILT animist who has taken the feat,
