ITEM 2 — metallic-reactance#instrument, phlogistonic-regulator#instrument      BUILT (route lifted)
--------------------------------------------------------------------------------------------------
TEACH — finding metallic-reactance#instrument and finding phlogistonic-regulator#instrument are both
settled by a new comparer host route, not by a data row: test/wg-experience.harness.test.tsx,
`function innovationModificationHost` (a FOURTH ownership route, called from `classFeatureHost` in
the `if (!fixed && !owner)` branch immediately before the UNSUPPORTED return). It seats a record
whose `otherTags` carry `<type>-innovation-modification` on the class that owns the matching
subclass (inventor / armor-innovation), with `inventorArmorStats` set from the record's own suit tag
and the record in the cheapest tier its level fits (`INVENTOR_TIER_LEVEL`); "without" is the same
inventor with `inventorModifications: {}`. The seat is CONFIRMED on a built character before the
host is handed back — `validPick` (src/rules/build.ts:8473) re-derives the offer, so a construct
modification (the dataset offers none) or a suit-gated one is not silently unheld, which would have
turned an unheld pick into a reported delivery gap.

Sweep result for both: verdict OK, deliveredBy differential, host
{classId inventor, subclassId armor-innovation, level 20, innovationTier initial}. The differential
moves 11 sheet paths each — resistances acid/electricity 13 (3 + half of 20) for Metallic Reactance,
cold/fire 10 for Phlogistonic Regulator, with `defenses.sources.resistance:*` naming the record —
against WG's two `adjValue RESISTANCES` ops.

off, classFeatureHost returns supported:false with the parked reason string, for both records. The

after that row and never a patched-vs-shipped delta.


ITEM 3 — lesson-of-vengeance#experience-flag, lesson-of-elements#experience-flag   BUILT (route lifted)
--------------------------------------------------------------------------------------------------
TEACH — finding lesson-of-vengeance#experience-flag and finding lesson-of-elements#experience-flag
are settled by a FIFTH ownership route: test/wg-experience.harness.test.tsx,
`function featChoiceHost`. It finds the LOWEST-level feat whose `choice.ownsFeature` offers the
record (the `aon-` prefix and the ownsFeature gate are both left to `choiceOwnedFeatureIds`, which is

in both builds and only what the chosen feature adds is counted.

No src/rules/derive.ts change was needed: `choiceOwnedFeatureIds` is already exported and already the
app's route, so the harness only had to call it. (The brief allowed for derive.ts being required and
for reporting it as a cross-file gap; it was not required.)

Sweep result: both OK, deliveredBy differential, host {classId witch, level 20, slotKey '2:class:0',
slotRendered true, via basic-lesson, without 'pick-unanswered'}. lesson-of-vengeance moves 9 sheet
paths — needle-of-vengeance into the witch focus repertoire with `spellSources` naming the lesson,
and phantom-pain into the familiar's spellbook — against WG's two giveSpells. lesson-of-elements
moves 7 AND adds one control, the "Familiar spell" popup on the Basic Lesson subcard with 4 options,
which is WG's `select from:SPELL "Select a Spell"` with its four options.
