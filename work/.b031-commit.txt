Three driver guards came out of that stall, each with a test:
- scripts/wg-batch-run.mjs precheck (1b): a manifest that CREATES a record in one spec and ASSIGNS a
  field of that same record in another is refused BEFORE writing, naming both rows and saying to fold
  the field into the create row. keyOf ends a create row with "(create)" and a field row with the field
  name, so the collision check never saw these two as one record, and the mistake could only surface as
  a post-check refusal after everything had been written. A field row byte-identical to what the create
  row already says, applied after it, is allowed - that is the shape this batch ships.
- scripts/wg-batch-run.mjs precheck (2) and the same check in scripts/apply-parity-fixes.mjs: a row
  byte-identical to the one already in the overlay no longer demands supersedes:true. A stage that
  refuses AFTER writing leaves the batch's own rows on disk, and re-running read all 22 of them as
  undeclared supersessions.
- scripts/wg-batch-run.mjs stageGaps: only queue entries no desk array holds yet are handed to
  add-owner-question.mjs, which refuses an id already on the desk and then writes nothing for the whole
