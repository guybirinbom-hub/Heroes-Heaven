WHAT WAS BUILT — THE TEACHES (all three files are inside stash@{0})
------------------------------------------------------------------
ONE ROOT CAUSE covers 38 of my 41 findings, and it is this project's signature bug: three comparers
credit a class's option list to the feature the class DECLARES as its carrier (`subclass.featureId`,
`extraChoices[].featureId`) and NEVER to the OPTION RECORD ITSELF — which is the record the comparison
actually lands on. Every witch patron, druid order, gunslinger way, summoner eidolon, investigator
methodology, wizard arcane school and animist apparition is a prose stub in `classFeatures` whose whole
mechanic lives on `classes.<cls>.subclass.options[<same id>]` / `extraChoices[].options[<same id>]`.

TEACH 1 — scripts/wg-values.mjs, `optionCarriers` + the reader at the end of `ourValues`
  id -> the option objects of that id, built once from every class's subclass.options and
  extraChoices[].options. The reader asserts `o.grants.skills` as trained, `o.grants.lores` as trained,
  and EVERY RUNG of `o.loreProgression` (so a ladder that stops short of the printed rank still reports
  DIFFERENT rather than being excused).

TEACH 2 — scripts/wg-values.mjs, `advancementByOptionTable`
  src/rules/advancement.ts is keyed `<classId>` AND `<subclassId>`; a subclass key is a COMPLETE table
  that replaces the class default (the file's own note names "warpriest, battle-creed"). Its rows carry
  the printed CLAUSE in `source` ('initial-creed', 'major-creed', 'true-creed'), never the subclass id,
  so `advancementBySource.get('battle-creed')` was empty. Bounded deliberately: ONLY a table key that is
  also a subclass-option id is credited, so class-keyed tables ('druid', 'cleric') are credited to
  nobody and keep reporting.

TEACH 3 — scripts/wg-values.mjs, `whileActive[].resistances / .weaknesses` in the SET collector
  Raging Resistance is state-gated by construction, so every instinct authors it as
  `whileActive [{state:'rage', minLevel:9, resistances:[…], weaknesses:[…]}]` (read by
  ownedWhileActive/activeStateGrants in derive.ts into the same IWR source list a flat field feeds).
  wg-diff already walks `whileActive` for KINDS; this is the same walk for SETS.

TEACH 4 — scripts/wg-values.mjs, a mode's `modifiers` with `target:'save'`
  The modes loop already read a mode's resistances and weaknesses; its `modifiers` were read by nobody.
  A `target:'save'` modifier is expanded into all three save tracks because WG splits the one printed
  sentence into SAVE_FORT / SAVE_REFLEX / SAVE_WILL — the same reasoning the item-shaped `pe.saves`
  scalar already uses. MAGNITUDE, so a mode carrying the wrong number still reports DIFFERENT.

TEACH 5 — scripts/wg-identity.mjs, `optionCarriers` + `optionDeclarer` + the reader in `ourIdentities`
  Credits the option's own `focusSpells`, `advancedFocusSpell`, `grantedSpells`,
  `grantedSpellChoice.options` (as both spells and options), `grantedFeats`, `featureIds[].id` and
  `tradition`; plus the per-option LADDER the DECLARING feature keeps
  (`classFeatures/conscious-mind.grantedSpells['the-distant-grasp'] = [{vector-screen,6},…]`), a home no
  reader here had ever looked in.

TEACH 6 — scripts/wg-identity.mjs, `creditOptions` bug fix
  It read `o.grants?.feats`, a field NO option in core.json carries. The real field is `grantedFeats`.
  `advancedFocusSpell` and `grantedSpells` were in no option reader at all. All three added, so the
  DECLARING selector under-reads no longer either.

TEACH 7 — scripts/wg-diff.mjs, the option-carrier branch at the end of `ourKindsOf`
  The same map for KINDS: grants.skills/.lores/loreProgression -> skill, grants.weapons -> weapon,
  grants.armor -> defense, focusSpells/advancedFocusSpell/grantedSpells -> spell, grantedSpellChoice ->
  spell+choice, skillChoice -> choice+skill, tradition -> spellcasting, grantedFeats/featureIds ->
  grantsRecord. An option carrying none of them credits nothing, so an unbuilt subclass keeps reporting.
