ITEM 2 — gap E: the speed-boosters Overdrive step                                   [BUILT]
--------------------------------------------------------------------------------------------
TEACH: finding hyper-boosters#overdrive (CONFIRMED) — its follow-through onto the record underneath it.

classFeatures/speed-boosters was {landSpeedBonus:5} with no whileActive, so a speed-boosters-only
inventor read +5 feet whether Overdrive was on or off, against innovation-5's "You gain a +5-foot
status bonus to your Speed, which increases to a +10-foot status bonus when under the effects of
Overdrive." WG agrees and was stricter than us: one conditional, +5 status out of Overdrive / +10 in.

TWO rows, because the proposed row alone would have been WRONG. Batch 036's own
requiresModification row makes speed-boosters a hard prerequisite of hyper-boosters, so the pair is
inseparable and every hyper-boosters number is a DELTA over the speed-boosters number underneath it —
which is exactly why hyper-boosters.landSpeedBonus was already superseded 10 -> 5 this batch with the
note "derive.ts ADDS the two". deriveSpeeds adds whileActive land grants the same way (derive.ts:5233
pushes each into grantSources; :5310 does `speeds.land = (speeds.land ?? 0) + v`), so a new
speed-boosters +5 beside the shipped hyper-boosters +10 would have paid the pair +25 feet in Overdrive
against a printed +20.
  classFeatures/speed-boosters.whileActive = [{state:"overdrive",speeds:{land:5}}]                    (first assignment)
  classFeatures/hyper-boosters.whileActive = [{state:"overdrive",speeds:{land:5}}]  supersedes:true    (was land:10)
The superseded array held one clause and nothing else, so the whole superseded value is carried into
the new one with only its number changed.
Arithmetic, both printed numbers exactly:
  speed-boosters alone   base 5            Overdrive 5+5   = +10
  the pair               base 5+5 = +10    Overdrive +10 +5+5 = +20

DECLARED, per the standing rule: hyper-boosters.whileActive is a field ANOTHER family's row applied
earlier in this batch (work spec -> scripts/data/effect-backfill.json). It is superseded here, not
edited: gap E is the verifier's own parked line, no family was assigned either record's whileActive in
the RED round, and both records' whileActive is now authored in one place — this spec.
